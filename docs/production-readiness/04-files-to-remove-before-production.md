## Explicit `.gitignore` gap found

The root `.gitignore` does **not** cover a bare `test-results/` directory at the repo root (it only implicitly relies on `e2e/.gitignore` for `e2e/test-results/`). A Playwright run launched from the repo root (rather than from `e2e/`) — which has happened at least once in this project's history per prior session notes — writes to `./test-results/` instead, which is currently untracked but **unprotected**: a careless `git add -A` at the repo root would stage it. Recommend adding one line to the root `.gitignore`:

```
test-results/
```

This is a one-line, low-risk documentation-adjacent fix. Per your instructions, this has **not** been applied — flagging it here and in the risk register for your explicit approval.

## Docker build context check — verified

Every app and backend service has its own `.dockerignore` (`apps/frontend-portal`, `apps/contractor-portal`, `apps/mobile-pwa`, and all 8 `services/*`, 11 files total). Each one excludes `node_modules`, `dist`, `.git`, `.env`/`.env.*`, `*.log`, and `coverage`. This is correct and requires no action — an unscoped `COPY . .` in any of these Dockerfiles will not pick up secrets, build artifacts, or VCS metadata. No gap found here.
